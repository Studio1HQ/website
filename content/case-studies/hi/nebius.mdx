Studio1 partnered with **Nebius** to grow developer adoption of Nebius Token Factory. The aim was simple: get developers building on Token Factory, not just reading about it.

## At a glance

* **Client:** Nebius Token Factory, a platform to build, fine-tune, and run open models at production scale
* **Services:** launch demos, technical content and video, framework integrations, open-source examples, workshops, and community distribution
* **Results:** a launch demo with **588K views**, a build article with **124K+ views**, a **16K+ star** open-source library, and **29 integrations**

## About Nebius

[**Nebius**](https://nebius.com) builds cloud infrastructure for AI teams. **Nebius Token Factory** is its platform to build, fine-tune, and run open models at production scale, behind an OpenAI-compatible API.

Token Factory's audience is developers choosing where to run and serve models, and they decide by trying things, not by reading positioning.

## The challenge: turning developer attention into hands-on exploration

Token Factory competes for developers who choose by building. Nebius needed developers to find the product where they already work, and to see proof they could run:

* Presence inside the frameworks and gateways developers already use
* Working examples built on Token Factory models
* Hands-on events that end with the product in use
* Visibility at every launch and new model

## Our approach

Four ideas shaped everything we built for Nebius:

* **Show, don't tell.** Developers trust a working app more than a feature list, so the default answer to "how do we explain this?" was "build something with it."
* **Meet developers where they already are.** The frameworks they use, the communities they read, and the events they attend matter more than any landing page.
* **Move at launch speed.** A new model is news for a few days. The work has to be ready while developers are paying attention, not a week later.
* **Leave something runnable behind.** Every piece ends with code a developer can clone and run on Token Factory, so interest turns into usage.

## The outcomes

### 1. Launch demos that developers shared

A model launch is when developers are most curious, and the window is short. Benchmark tables rarely travel, so for each launch we built something visual that a developer could open, play with, and share, with the code behind it ready to run on Token Factory.

Each demo was designed to stand on its own: one clear idea, a working app, and a short video. Nebius shared them with its own audience, which put the new model and the platform in front of developers at exactly the right moment.

One of them, a 3D explainer that takes any machine apart piece by piece, reached **588K views** on Nebius's X account in under two weeks.

### 2. An open-source library that became a showcase

Developers trust code they can run more than claims they can read. So we built an open-source collection of **130+ runnable agent examples** on Token Factory models, organised by what developers want to build, such as RAG, voice, memory, or MCP, rather than by product feature. Each example is self-contained, so a developer can clone one folder and have it working in minutes.

Keeping it maintained matters as much as growing it. Examples are updated as frameworks and models change, so the library stays useful long after a launch. It has passed **16K GitHub stars** and trended on GitHub twice.

### 3. Available in the tools developers already use

Most developers won't switch tools to try a new model provider. Rather than asking them to come to Token Factory, we brought Token Factory to them, working with the maintainers of popular agent frameworks, AI gateways, and developer tools so Nebius shows up as a first-class option.

Each integration is a small change for a developer and a lasting channel for Nebius: everyone who picks up those tools can find Token Factory without looking for it. Nebius is now available in **29 frameworks, gateways, and developer tools**.

### 4. Content that reaches developers

Our content follows one rule: every piece should end with something the reader can run. Articles, tutorials, comparisons, and videos follow the product as it grows, from new models to fine-tuning and agents, and they're written by engineers who build with the product, not just describe it.

Timing matters too. When a question is already trending, a hands-on answer built on Token Factory travels much further than an announcement. One long-form [build article on X](https://x.com/Arindam_1729/status/2109722598406025614), made with open models on Token Factory, passed **124K views**.

### 5. Hands-on events

Events are where interest turns into use. Our workshops are built around a real project, so developers leave with something working on Token Factory, not just a slide deck.

We also co-host sessions with other developer tools. A joint workshop brings in an audience that might never have found Nebius on its own, and shows Token Factory working alongside tools they already know. Workshops, meetups, and conference talks have put Token Factory in front of developers across Europe, the US, and India.

### 6. Community distribution

We don't post the same link everywhere. Each piece is adapted to the community where its topic is already being discussed, written for that audience and that format, so it reads as a contribution rather than an ad.

That approach earned real attention: posts in AI, agent, and LLM communities on Reddit reached **hundreds of thousands of views**, and several were featured in developer newsletters.

## Why it worked

The work covered the whole path a developer takes: finding Token Factory inside a familiar framework, seeing it work in an example, building with it at an event, and meeting it again at each launch. Because one team ran all of it, the story stayed the same at every step.

Speed mattered too. A new model is news for a few days, so the demos were ready while developers were paying attention.

For an infrastructure product, that continuity is the point. Developers choose by building, so everything we shipped was designed to get them building.

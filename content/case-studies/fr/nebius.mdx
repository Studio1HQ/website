Studio1 works with **Nebius** as an embedded developer-growth partner for Nebius Token Factory, and has for nearly two years. The work spans Day-0 launch demos, content and video, framework integrations, open-source examples, developer tools, live events, and launch support.

The goal was never volume for its own sake. Every piece is meant to end with a developer building on Token Factory.

## At a glance

* **Client:** Nebius Token Factory, Nebius's platform to build, fine-tune, and run open models at production scale
* **Services:** Day-0 launch demos, technical content and video, framework integrations, open-source examples, workshops, and community distribution
* **Recent highlights (November 2026):** six launch apps for Kimi K3.1 Pro merged into the official cookbook in launch week, and one of them, Cutaway, reached **588K views** on Nebius's own X account
* **Across the engagement:** **400+ deliverables**, **29 integrations**, and a **16K+ star** open-source library

## About Nebius

[**Nebius**](https://nebius.com) builds cloud infrastructure for AI teams. Our work centers on **Nebius Token Factory**, its platform to build, fine-tune, and run open models at production scale, with serverless and dedicated endpoints, post-training, and data tooling behind an OpenAI-compatible API.

Token Factory's audience is developers choosing where to run and serve models, and they decide by trying things, not by reading positioning.

## The challenge: turning developer attention into hands-on exploration

Token Factory competes for developers who choose by building. Nebius needed a program that put the product where developers already work, with proof they could run:

* Presence inside the frameworks and gateways developers already use
* Working examples built on Token Factory models
* Hands-on events that end with the product in use
* Coverage of every launch and new model as it happens

## Our role

Studio1 works as an extension of the Nebius team across the full developer-growth workflow:

* **Day-0 launch demos:** working apps on new models, shipped in launch week
* **Content and video:** articles, tutorials, demos, and short-form posts
* **Integrations:** getting Nebius added to the frameworks and gateways developers use
* **Open-source examples:** a maintained library of agent apps on Token Factory
* **Developer tools and apps** built on Token Factory models
* **Workshops, talks, and meetups**
* **Community distribution** and launch support

## What we delivered

### 1. Day-0 demos for new models

When a new model lands on Token Factory, we build apps that show what it can do, add them to Nebius's official [Token Factory Cookbook](https://github.com/nebius/token-factory-cookbook), and post them on X while the launch is still news.

For **Kimi K3.1 Pro** in November 2026, we built six apps: **Cutaway**, **Explode Anything**, **Codetrail**, **Napkin to 3D Print**, **Paper to Interactive Explainer**, and **Sketch to Walkthrough**. Nebius merged all six into the cookbook on 5 November, three of them as Token Factory-branded editions.

* **Cutaway** turns the name or photo of any machine into an interactive 3D model you can pull apart, part by part. Nebius posted it from [@nebiustf](https://x.com/nebiustf/status/2118407100799893901), credited to our engineer: **588K views, 1.2K likes, and 185 bookmarks** in under two weeks. Anyone can try it at [nebius-tf-cutaway.lovable.app](https://nebius-tf-cutaway.lovable.app/).
* **Napkin to 3D Print** turns a sketch into a printable 3D model. Our [launch post](https://x.com/Arindam_1729/status/2118064983464640611) passed **4.6K views**.
* For **Inkling 2 Small**, we shipped a cookbook project, a quickstart, and a model guide ([merged 13 November](https://github.com/nebius/token-factory-cookbook/pull/99)), plus a Day-0 demo that turns a hand-drawn circuit into a working simulation.

The cookbook is where this work lasts: since July 2025 it has collected our agent examples and full apps, so developers who find a launch post later still land on code they can run.

### 2. An open-source library that became a Token Factory showcase

Studio1 maintains **[awesome-ai-apps](https://github.com/Arindam200/awesome-ai-apps)**, an open-source collection of **130+ runnable agent examples** built on Nebius Token Factory models across the major agent frameworks. Each one covers a real use case, such as RAG, voice, memory, or MCP, so developers can see Token Factory working before writing their own code.

The repo has grown past **16K GitHub stars** and trended on GitHub twice.

### 3. Integrations across the developer ecosystem

We got Nebius added to **29 frameworks, gateways, and tools**, including LangChain, CrewAI, LlamaIndex, Agno, LiteLLM, Pipecat, LiveKit, mem0, AWS Strands, and Vercel AI Gateway. Developers could pick Token Factory models without leaving the tools they already used.

### 4. Content, video, and long-form articles

Across the engagement we have shipped **45+ articles** (including official Nebius blog posts), **40+ videos and shorts**, and a steady stream of posts on X, LinkedIn, and developer communities. Coverage follows the product: new models, fine-tuning, agents, MCP, batch inference, observability, and Data Lab.

Long-form articles on X turn a timely question into a build on Token Factory:

* **[Build your own Jev in 15 minutes](https://x.com/Arindam_1729/status/2109722598406025614):** when Jev's decision model went viral, we rebuilt it with open models on Token Factory, from a zero-shot classifier to a fine-tune that answered about 2x faster in our tests. **124K+ views.**
* **[Kimi K3.1 Pro is 5.4x cheaper than Opus 5.5](https://x.com/Arindam_1729/status/2120596778479493254):** the same tasks run on both models, measuring what each task actually costs on Token Factory, not the price per token.
* **[Proactive Agents: clearly explained](https://x.com/Arindam_1729/status/2122631856885846094):** an on-call agent that runs on a schedule with Kimi K3.1 Pro on Token Factory.

## Why it worked

The program covers the whole path a developer takes: discovering Token Factory inside a familiar framework, seeing it work in an example, building with it in a workshop, and finding it again at each launch. One partner running content, integrations, events, and launches means the same story reaches developers at every step.

Speed matters as much as coverage. A new model is news for a few days, so the demos ship in launch week, land in the official cookbook, and go out from Nebius's own account while developers are still paying attention.

For an infrastructure product, that continuity is the point. Developers choose by building, so everything we ship is designed to get them building.
